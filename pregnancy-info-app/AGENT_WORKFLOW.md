# Everwell — multi-agent execution and quality control
Owner directive 2026-11-27. Applies to all models, Cursor, ChatGPT, and other workers. This is an operational contract, not a claim that any particular tool supports multi-agent execution.

## Required first-read order
1. START_HERE.md and this document; then COMPLETION_CHECKLIST.md and design/VISUAL_ACCEPTANCE_STANDARD.md.
2. CURSOR_USAGE_STRATEGY.md, DESIGN_SYSTEM.md, PLATFORM_REQUIREMENTS.md, MEDICAL_SAFETY.md, PRIVACY.md, research/INDEPENDENT_EVIDENCE_REVIEW.md, and publication gate.
3. Inspect both main and everwell-iphone-preview, compare heads and current deployment, read existing handoffs and open checklist items. Main holds research and governance; preview currently contains newer app code. Do not reset preview to main, overwrite either branch, or touch unrelated SPYDER. Integrate intentionally, review conflicts, no force push.
4. Read the actual reference images and latest owner feedback; do not invent fidelity from a description. Audit actual model availability, included usage, reset and budget per CURSOR_USAGE_STRATEGY.md. Protect 10% of remaining included allowance, no extra paid work without explicit approval. If unavailable, record limitation and request owner snapshot as required by that policy.

## Hierarchy and responsibility
Owner: product decisions, acceptance of rendered design and clinical release authorization (clinical review also mandatory). Project lead/orchestrator: decomposes tasks, assigns owners, sets reference/acceptance criteria before work, tracks dependencies and budget, reviews diffs, integrates changes, updates checklist and handoff. Lead architect: maintainable architecture, state, routes, build and data contract. Design lead: reference fidelity, typography, layout, illustration direction, actual screen composition; no unauthorized theme changes. UI implementation workers: narrowly scoped component/routes, actual functioning implementation, no simultaneous edits to shared files. Research/evidence worker: independent source appraisal, funding, conflicts, citation integrity, uncertainty; not UI decisions. Medical safety/privacy reviewer: independent safety/hold/licensing/storage review with veto on unsafe changes; qualified human clinical review still required. QA automation worker: lint, type check, unit tests, data validation, browser task paths, viewport and offline checks. Independent visual reviewer: inspect captured actual app screenshots without relying on implementer's favorable summary; compare to reference and last accepted screenshot. Release integrator: only after required review gates; protect preview, verify exact deployed commit and URL, record rollback target. Human owner verifies final visual acceptance; no public release without authorization.
Use real subagents when tool supports them, preferably different model/context for independent review; parent delegates distinct objectives and budgets. Cheap models for mechanical work, capable reasoning models for integration and independent review, vision-capable models for screenshots, research models for evidence. No fixed model IDs or pricing assumptions. Workers receive immutable brief, relevant files, checklist IDs, reference assets, acceptance checks and allowed paths. Workers work in separate worktrees/branches where available. Lead owns shared CSS/routing/data integration. A reviewer may not approve its own work as independent. If subagents unavailable, explicitly record that and conduct sequential role-specific passes; do not invent identities, results or independence. Critical independent/human gates stay open.
## Execution cycle
Plan small batches with baseline commit, owner acceptance goal, screenshot reference and test plan. Capture BEFORE actual-app screenshots at relevant sizes/states. Assign workers in parallel only for non-conflicting files. Build actual app; capture AFTER from actual built React application, not mock HTML or generated image. Compare side-by-side; inspect spacing, visual hierarchy, taps, safe areas, short viewport, keyboard, focus, back state. Run all automated gates; validate content/data/holds. Independent reviewers report findings and severity with screenshot/test evidence. Fix P0/P1 before preview handoff; preserve last acceptable build if gate fails. Preview deployment is authorized only for owner testing on existing protected Vercel project, never public production; do not weaken access protection. Existing public repo does not make clinical data approved. No recurring monitoring. Record exact branch, SHA, environment, commands, counts, screenshots, unresolved issues, rollback, and honest scope. Owner visual approval is separate from code/test success. Check off only verified tasks; reopen on regression. No “finished” claim with open release gates.
## Review severity
P0: safety/privacy/security, lost data, broken primary app, hold bypass. P1: reference mismatch, blocked primary task, major accessibility, missing navigation. P2: localized polish or secondary friction. P3: improvement. P0/P1 block owner-ready design claims. If no actual browser available, stop before claiming visual verification; code may be committed as a candidate, protected preview for testing only with explicit limitation.
## Worker return template
Task ID | role/model actually used | base SHA | changed files | evidence/commands | findings by severity | tests passed/failed/not run | screenshots paths/viewport | open blockers | recommendation. Lead updates checklist once evidence reviewed.
