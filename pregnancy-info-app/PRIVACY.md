# Privacy and security requirements

This repository is public at transfer time. It must contain no real health records, identifiers, photographs, reproductive history, personal timelines, journal entries, secrets, tokens or private account data. Use generic demonstration fixtures only, clearly labeled. A private repository is advisable before adding sensitive project material, but never use Git for storing actual personal records even if private.

Design for local-first sensitive storage, explicit consent for any transfer, minimal collection, export and deletion, optional tracking disabled by default, secure storage appropriate to the platform, and separate public research data. Avoid advertising and unnecessary analytics. Document dependencies and external services. Do not enable cloud sync, deploy the app or transmit private data without explicit approval. Add suitable ignore rules and secret checks. Use safe generic sample records and keep credentials in approved secret management, never in code.

## Stage 4 local preference implementation · 2026-11-27

Optional reading-phase IDs, bookmarks, manually marked reading items and theme live in browser localStorage under `everwell.local.prefs.v1`. No phase assumed; default-only state removes the key. Search is transient, and no new external transmission or analytics is implemented. These preferences can indirectly reveal health interests and are not encrypted; shared-device users should be able to clear them. Library provides explicit export display and confirmed deletion. Do not mistake this limited preference storage for secure personal health storage. No actual health records or personalized clinical decision paths authorized. Runtime storage, offline cache, network requests (including existing fonts/dependencies), shared devices and cross-tab behavior require separate verification before release.

## Private preview protection, November 27, 2026
Preview configuration adds a restrictive Content Security Policy: same-origin scripts (with exact inline theme bootstrap hash), connections, media, workers and fonts; no framing or form submission; same-origin/data images only. Inline styles remain permitted for existing interface styling. No-referrer, nosniff and camera/microphone/geolocation restrictions are specified. Build postcheck validates entry HTML assets, script hash and policy configuration. Static verification is not an authenticated HTTP header or live browser network audit. Existing Vercel access protection remains required. Open reading sections and visual-list expansions are transient in-memory UI preferences, not exported or persisted. Browser history, shared-device exposure, offline cache, and authenticated network behavior remain open for review.
