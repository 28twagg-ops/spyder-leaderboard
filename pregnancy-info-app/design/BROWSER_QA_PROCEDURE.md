# Actual app browser QA — PC procedure

This is the next required visual gate, not a claim that browser tests have already been executed. The script uses a disposable Chromium browser context and the real built React application. It does not open the protected Vercel URL, use a real profile, install dependencies automatically, send information to a server or launch paid cloud workers.

1. Work on the latest `everwell-iphone-preview` branch in `pregnancy-info-app/app`. Confirm the commit and preserve local changes. Read AGENT_WORKFLOW and the canonical checklist on main.
2. Run `npm ci`, `npm run lint`, `npm test`, and `npm run build`. Use the documented Node version.
3. Ensure a reviewed local Playwright installation (and Chromium, or set CHROME_PATH to an existing compatible browser). Do not alter committed dependency versions merely to execute QA. The script is stored on main at `pregnancy-info-app/design/qa-browser.mjs`; obtain that file from main into a temporary local path, then execute `node /path/to/qa-browser.mjs /absolute/path/to/pregnancy-info-app/app`. Example from the app directory, after fetching main on macOS/Linux: `git show origin/main:pregnancy-info-app/design/qa-browser.mjs > /tmp/everwell-qa-browser.mjs` then `node /tmp/everwell-qa-browser.mjs .`. On Windows use a temporary folder outside the repository. Output uses qa-artifacts.local/, covered by the existing app .gitignore pattern *.local.
4. Inspect qa-artifacts.local/report.json and screenshots. Record actual commit, browser and result. Do not upload personal screenshots or real preferences. Review shortControls manually: inline controls, visually hidden controls and minor measurement variation need judgment. Check all failures, compare with reference artwork and last owner-accepted actual screenshots. Repeat after corrections.
5. This is Chromium responsive emulation, not iPhone Safari, VoiceOver or installed PWA acceptance. Manually test these, 200% text, keyboard, device/browser safe areas, update behavior and actual iPhone setup. Require independent visual review where available and owner acceptance. No public clinical release.

The script is an unexecuted QA candidate in this chat because the local environment cannot retrieve the current application source/build and independent agents are unavailable. Validate the harness itself in the first PC run; fix any selector/runner assumptions without weakening meaningful assertions. Do not represent a successful fixture or unit test as actual visual verification.

The runner now includes the urgent infant reader and separate optional reading layer, and checks that the archive stays collapsed. These added checks still require an actual local run. The main checklist is authoritative for verified evidence, not the existence of a QA script.
